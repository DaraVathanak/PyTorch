What is PyTorch?

Understand what PyTorch is, why it matters, and how to install it.

🔍 What is PyTorch?

PyTorch is an open-source machine learning framework developed by Meta AI (formerly Facebook). It provides a flexible and intuitive platform for building deep learning models with dynamic computational graphs.

💡 Why Choose PyTorch?
  • Pythonic: Feels like native Python — easy to learn and debug
  • Dynamic Graphs: Build and modify networks on-the-fly (eager execution)
  • GPU Acceleration: Seamlessly move computations to GPU with .to('cuda')
  • Research Favorite: Most popular framework in AI research papers
  • Production Ready: TorchScript and ONNX export for deployment

Autograd: Automatic Differentiation

The engine behind neural network training — computing gradients automatically.

🧮 What is Autograd?

Autograd is PyTorch's automatic differentiation engine. It records all operations on tensors to build a computational graph, then uses this graph to compute gradients via backpropagation.

Computational Graph

📐 Computing Gradients

Python 
import torch

# Create tensor with gradient tracking
x = torch.tensor(3.0, requires_grad=True)

# Forward pass: build computational graph
y = x ** 2          # y = x²
z = 2 * y + 3       # z = 2x² + 3

# Backward pass: compute gradients
z.backward()        # dz/dx = 4x

print(f'x = {x.item()}')
print(f'z = {z.item()}')
print(f'dz/dx = {x.grad.item()}')  # 4 * 3 = 12
Output: 
x = 3.0
z = 21.0
dz/dx = 12.0

⚠️ Important: Gradient Accumulation

🚨 Gradients Accumulate!

PyTorch accumulates gradients by default. You must zero them before each backward pass during training:

Python 
# In your training loop:
optimizer.zero_grad()    # Clear old gradients
loss.backward()          # Compute new gradients
optimizer.step()         # Update weights

🚫 Disabling Gradient Tracking

Python 
# Method 1: Context manager (recommended for inference)
with torch.no_grad():
    prediction = model(x)

# Method 2: Detach from graph
x_detached = x.detach()

# Method 3: Set requires_grad
x.requires_grad_(False)

nn.Module Deep Dive

Learn to build custom neural networks using PyTorch's Module system.

🏗️ Custom nn.Module

Every neural network in PyTorch inherits from nn.Module. You define layers in __init__ and the computation in forward.

Python 
import torch.nn as nn
import torch.nn.functional as F

class MultiLayerNet(nn.Module):
    def __init__(self, input_size, hidden_size, num_classes):
        super().__init__()
        self.fc1 = nn.Linear(input_size, hidden_size)
        self.bn1 = nn.BatchNorm1d(hidden_size)
        self.fc2 = nn.Linear(hidden_size, hidden_size)
        self.bn2 = nn.BatchNorm1d(hidden_size)
        self.fc3 = nn.Linear(hidden_size, num_classes)
        self.dropout = nn.Dropout(0.3)
    
    def forward(self, x):
        x = F.relu(self.bn1(self.fc1(x)))
        x = self.dropout(x)
        x = F.relu(self.bn2(self.fc2(x)))
        x = self.dropout(x)
        x = self.fc3(x)
        return x

model = MultiLayerNet(784, 256, 10)
print(model)
print(f'\nTotal parameters: {sum(p.numel() for p in model.parameters()):,}')

import torch
import torch.nn as nn

class CustomMLP(nn.Module):
    def __init__(self, in_features=10, hidden=32, out_features=2):
        super().__init__()
        self.fc1 = nn.Linear(in_features, hidden)
        self.relu = nn.ReLU()
        self.dropout = nn.Dropout(0.3)
        self.fc2 = nn.Linear(hidden, out_features)

Training & Validation Loops

The complete training pipeline with validation, metrics, and best practices.

🔄 Complete Training Loop

Python 
def train_one_epoch(model, loader, criterion, optimizer, device):
    model.train()
    running_loss = 0.0
    correct = 0
    total = 0
    
    for inputs, targets in loader:
        inputs, targets = inputs.to(device), targets.to(device)
        
        optimizer.zero_grad()
        outputs = model(inputs)
        loss = criterion(outputs, targets)
        loss.backward()
        optimizer.step()
        
        running_loss += loss.item()
        _, predicted = outputs.max(1)
        total += targets.size(0)
        correct += predicted.eq(targets).sum().item()
    
    return running_loss / len(loader), 100. * correct / total

def validate(model, loader, criterion, device):
    model.eval()
    running_loss = 0.0
    correct = 0
    total = 0
    
    with torch.no_grad():
        for inputs, targets in loader:
            inputs, targets = inputs.to(device), targets.to(device)
            outputs = model(inputs)
            loss = criterion(outputs, targets)
            
            running_loss += loss.item()
            _, predicted = outputs.max(1)
            total += targets.size(0)
            correct += predicted.eq(targets).sum().item()
    
    return running_loss / len(loader), 100. * correct / total

📐 The Conv2D Output Shape Formula

🧮 How to Calculate Output Dimensions (Avoid Shape Mismatch!)

To know the shape after any convolution layer, use this exact mathematical formula:

Output Size = ⌊ (Input Size - Kernel + 2 × Padding) / Stride ⌋ + 1
Step-by-Step Shape Walkthrough:
[B, 1, 28, 28] Input Grayscale Image Batch
[B, 32, 28, 28] After Conv2d(1, 32, k=3, p=1): (28 - 3 + 2)/1 + 1 = 28
[B, 32, 14, 14] After MaxPool2d(2, 2): Dimensions halved (28 / 2 = 14)
[B, 64, 7, 7] After Conv2 + Pool2: 14 halved to 7 • Total flat features = 64 × 7 × 7 = 3,136

        super().__init__()
        assert d_model % num_heads == 0
        self.d_k = d_model // num_heads
        self.num_heads = num_heads
        
        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.W_o = nn.Linear(d_model, d_model)

        batch_size, seq_len, d_model = x.shape

            batch_size, seq_len, self.num_heads, self.d_k

            batch_size, seq_len, self.num_heads, self.d_k
        ).transpose(1, 2)

            batch_size, seq_len, self.num_heads, self.d_k

import torch
import math

def scaled_dot_product_attention(Q, K, V, mask=None):
    # d_k is the head dimension (last dimension)
    d_k = Q.size(-1)
    
    # 1. Matmul Q and K transposed: (B, H, S, D) @ (B, H, D, S) -> (B, H, S, S)
    scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(d_k)
    
    # 2. Apply causal mask if present
    if mask is not None:
        scores = scores.masked_fill(mask == 0, -1e9)
        
    # 3. Softmax along sequence dimension
    attn_weights = torch.softmax(scores, dim=-1)
    
    # 4. Multiply with Value tensor: (B, H, S, S) @ (B, H, S, D) -> (B, H, S, D)
    context = torch.matmul(attn_weights, V)
    return context, attn_weights

    def __init__(self, latent_dim=100, channels=1):
        super().__init__()
        self.net = nn.Sequential(
            # latent_dim → 256 x 7 x 7
            nn.ConvTranspose2d(latent_dim, 256, 7, 1, 0, bias=False),
            nn.BatchNorm2d(256),
            nn.ReLU(True),
            # 256 x 7 x 7 → 128 x 14 x 14
            nn.ConvTranspose2d(256, 128, 4, 2, 1, bias=False),
            nn.BatchNorm2d(128),
            nn.ReLU(True),
            # 128 x 14 x 14 → channels x 28 x 28
            nn.ConvTranspose2d(128, channels, 4, 2, 1, bias=False),
            nn.Tanh()
        )
    
    def forward(self, z):
        return self.net(z.view(-1, z.size(1), 1, 1))

class Discriminator(nn.Module):
    def __init__(self, channels=1):
        super().__init__()
        self.net = nn.Sequential(
            nn.Conv2d(channels, 64, 4, 2, 1),
            nn.LeakyReLU(0.2, inplace=True),
            nn.Conv2d(64, 128, 4, 2, 1, bias=False),
            nn.BatchNorm2d(128),
            nn.LeakyReLU(0.2, inplace=True),
            nn.Flatten(),
            nn.Linear(128 * 7 * 7, 1),
            nn.Sigmoid()
        )
    
    def forward(self, x):
        return self.net(x)

import torch
import torch.nn as nn

criterion = nn.BCEWithLogitsLoss()

def discriminator_loss(d_real_logits, d_fake_logits, smooth=True):
    # One-sided label smoothing (0.9 instead of 1.0) prevents discriminator overconfidence
    real_targets = torch.full_like(d_real_logits, 0.9 if smooth else 1.0)
    fake_targets = torch.zeros_like(d_fake_logits)
    
    loss_real = criterion(d_real_logits, real_targets)
    loss_fake = criterion(d_fake_logits, fake_targets)
    return (loss_real + loss_fake) / 2.0

    # Generator wants discriminator to believe fakes are real (label=1.0)
    real_targets = torch.ones_like(d_fake_logits)
    return criterion(d_fake_logits, real_targets)

    # 6. Update weights: w = w - lr * grad
    optimizer.step()

    # Detach loss scalar to prevent memory leak
    running_loss += loss.item()

Trick #1: Automatic Mixed Precision (AMP)

Modern NVIDIA GPUs have Tensor Cores optimized for 16-bit floats (FP16/BF16). AMP automatically computes operations in FP16 while maintaining weights in FP32 with dynamic loss scaling.

❌ Naive Beginner Code Standard FP32 — Slow & High VRAM 
# Naive training step (Pure 32-bit float)
for x, y in dataloader:
    x, y = x.to(device), y.to(device)
    optimizer.zero_grad()
    out = model(x)
    loss = criterion(out, y)
    loss.backward()
    optimizer.step()
Why this is suboptimal: All weights, activations, and gradients are stored in 32-bit floats. Memory bandwidth becomes a major bottleneck and modern Tensor Cores remain idle.
✅ Pro Engineer Code torch.amp.autocast + GradScaler 
# Pro training step with AMP
scaler = torch.amp.GradScaler('cuda')

for x, y in dataloader:
    x, y = x.to(device), y.to(device)
    optimizer.zero_grad()
    
    # 1. Autocast forward pass to FP16 / BF16
    with torch.amp.autocast('cuda', dtype=torch.float16):
        out = model(x)
        loss = criterion(out, y)
        
    # 2. Scale loss to prevent underflow, then backprop
    scaler.scale(loss).backward()
    
    # 3. Unscale and step optimizer
    scaler.step(optimizer)
    scaler.update()
Why this works: Convolutions and Matrix Multiplications run at 16-bit precision on Tensor Cores. GradScaler dynamically multiplies the loss by $2^{16}$ during backprop to stop gradient numbers smaller than $10^{-7}$ from rounding to zero!
🧠

Under The Hood Engineering Mechanics

Modern GPUs have dedicated silicon (NVIDIA Tensor Cores) specifically wired to execute $4 \times 4$ half-precision matrix multiplications in a single clock cycle. By wrapping the forward pass in torch.amp.autocast(), PyTorch automatically casts compute-heavy operations (Linear, Conv2d) to float16, while keeping sensitive operations (Softmax, BatchNorm, Loss) in float32 for numerical stability.

The PyTorch Debugging Clinic

The 8 most common errors that stop beginners and professionals alike — explained with exact causes, buggy code, and bulletproof fixes.

Shape Error

RuntimeError: mat1 and mat2 shapes cannot be multiplied (32x512 and 256x10)

RuntimeError: mat1 and mat2 shapes cannot be multiplied (32x512 and 256x10)

Why this happens: The output features from your previous layer (512) do not match the expected in_features of your nn.Linear layer (256). For matrix multiplication $A \times B$, the inner dimensions must match exactly: $(32 \times 512) \times (512 \times 10)$.

❌ Buggy Code
# Feature size after convs is 512
x = torch.flatten(x, 1)  # shape: [32, 512]
# Error: Linear expected 256, but received 512!
fc = nn.Linear(256, 10)
out = fc(x)
✅ Fixed Code
# Check shape dynamically during debugging:
# print("Flatten shape:", x.shape)
x = torch.flatten(x, 1)  # [32, 512]
# Match in_features to 512:
fc = nn.Linear(512, 10)
out = fc(x)  # Success: [32, 10]
💡
Golden Rule: When debugging architecture shapes, temporarily add print("Shape:", x.shape) right before the offending layer in your forward() method.
Device Error

RuntimeError: Expected all tensors to be on the same device (cpu vs cuda:0)

RuntimeError: Expected all tensors to be on the same device, but found at least two: cpu and cuda:0!

Why this happens: You sent the model to GPU with model.to('cuda'), but your batch inputs or targets are still sitting on the CPU (or vice-versa). PyTorch cannot perform cross-device computations.

❌ Buggy Code
device = torch.device('cuda')
model = MyNet().to(device)

for images, labels in dataloader:
    # BUG: images still on CPU!
    outputs = model(images)  # CRASH!
✅ Fixed Code
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
model = MyNet().to(device)

for images, labels in dataloader:
    # Explicitly transfer tensors to target device:
    images = images.to(device, non_blocking=True)
    labels = labels.to(device, non_blocking=True)
    outputs = model(images)
💡
Golden Rule: Always define a central device variable and ensure both model.to(device) and batch.to(device) use the exact same variable.
Memory Leak

CUDA out of memory: Loss Accumulation Memory Leak

torch.cuda.OutOfMemoryError: CUDA out of memory. Tried to allocate 512.00 MiB (GPU 0; 8.00 GiB total capacity)

Why this happens: Writing total_loss += loss stores the full autograd computation graph of every batch in GPU memory across the entire epoch! PyTorch keeps all intermediate activation buffers alive because total_loss has a reference to the graph.

❌ Buggy Code
total_loss = 0.0
for x, y in loader:
    loss = criterion(model(x), y)
    loss.backward()
    optimizer.step()
    # FATAL: Retains computation graph of every batch!
    total_loss += loss  # Causes CUDA OOM after a few epochs
✅ Fixed Code
total_loss = 0.0
for x, y in loader:
    loss = criterion(model(x), y)
    loss.backward()
    optimizer.step()
    # SAFE: .item() extracts float, freeing the graph!
    total_loss += loss.item()
💡
Golden Rule: Never accumulate tensor loss directly in a list or sum. Always extract the raw Python float with loss.item().
Autograd Error

RuntimeError: element 0 of tensors does not require grad and does not have a grad_fn

RuntimeError: element 0 of tensors does not require grad and does not have a grad_fn

Why this happens: You called loss.backward(), but somewhere in your forward pass you detached the tensor, converted it to NumPy and back, or ran under with torch.no_grad():. This severed the computation graph, so PyTorch cannot track gradients.

❌ Buggy Code
def forward(self, x):
    h = self.fc1(x)
    # BUG: Converting to NumPy severs the graph!
    h_np = np.maximum(0, h.detach().numpy())
    h = torch.tensor(h_np)
    return self.fc2(h)
✅ Fixed Code
def forward(self, x):
    h = self.fc1(x)
    # Use native PyTorch operations to maintain graph:
    h = torch.relu(h)  # or F.relu(h)
    return self.fc2(h)
💡
Golden Rule: Never convert tensors to NumPy or call .detach() or .numpy() inside a model's forward() pass if you plan to train it.
Dtype Error

RuntimeError: Expected object of scalar type Long but got type Float for target

RuntimeError: Expected object of scalar type Long but got type Float for argument #2 'target' in CrossEntropyLoss

Why this happens: nn.CrossEntropyLoss expects integer class indices (0, 1, 2, ..., C-1) as a 64-bit integer tensor (torch.long or torch.int64), NOT floating-point numbers and NOT one-hot encoded vectors!

❌ Buggy Code
criterion = nn.CrossEntropyLoss()
targets = torch.tensor([0.0, 1.0, 2.0])  # Float!
loss = criterion(outputs, targets)  # CRASH!
✅ Fixed Code
criterion = nn.CrossEntropyLoss()
# Cast targets to torch.long:
targets = targets.long()  # or dtype=torch.int64
loss = criterion(outputs, targets)  # Works perfectly!
💡
Golden Rule: For multi-class classification with nn.CrossEntropyLoss, targets must be 1D torch.long class labels. For binary classification with nn.BCEWithLogitsLoss, targets must be torch.float32.
Binary Loss Error

ValueError: Target size must be the same as input size in BCEWithLogitsLoss

ValueError: Using a target size (torch.Size([32])) that is different to the input size (torch.Size([32, 1])) is deprecated.

Why this happens: Your model outputs logits of shape [Batch, 1] (from nn.Linear(in, 1)), but your dataset labels have shape [Batch] (1D array). In PyTorch, broadcasting will cause unintended mathematical errors or crashes.

❌ Buggy Code
outputs = model(inputs)   # shape: [32, 1]
targets = labels          # shape: [32]
loss = criterion(outputs, targets)  # Shape mismatch!
✅ Fixed Code
outputs = model(inputs)               # [32, 1]
targets = labels.unsqueeze(1).float() # [32, 1]
loss = criterion(outputs, targets)    # Perfect match!
💡
Golden Rule: Use targets.unsqueeze(1) to add the trailing singleton dimension to match model output shape.
